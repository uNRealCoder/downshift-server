Where the time of one request goes

For one request at a time, how many milliseconds go to parsing, waiting, inference, encoding and the HTTP stack?

Run 2026-11-07T22:59:00. win32, 16 logical CPUs, Python 3.12.10, torch 2.14.0+cpu, onnxruntime 1.30.0. downshift 1.0.0rc1 from the checkout, 0.5.1 from PyPI. The folder is named v1.0.0.

The question

A request has a fixed part (HTTP, JSON, thread hand-offs) and a model part. On a tiny model the fixed part is most of the time. On an encoder the model part is most of the time. This page splits the time of one request into stages.

Method

  • The harness sends 300 requests one after the other on one keep-alive connection. Batch 1 (MiniLM: one sentence). It takes the median of each value.
  • total is what the client measured. The stage values are the Server-Timing header of the server. Hand-rolled servers have no such header.
  • HTTP + hand-offs is not measured directly. It is the client total minus every stage. It holds uvicorn, routing, middleware and thread hand-offs back to the event loop. For a hand-rolled server it is the whole total.
  • Data: bench/results/v1.0.0/chart_stages.csv. Made by bench.report --stages-csv from results.json and results_hf.json.

What this shows and does not show

Shows

  • On clean_mlp the model needs 0.13 ms of 0.70 ms. The rest is the fixed cost of the request path.
  • On MiniLM the ONNX Runtime backend spends 3.00 ms in inference. The torch backend spends 8.56 ms on the same input. The other stages are close.
  • The prep, wait and encode stages of downshift are each below 0.4 ms in this file for all five models.

Does not show

  • Time under load. These are sequential requests. Queueing at high concurrency is not in this table.
  • Where the HTTP stack time goes inside. The file has one derived value, not a profile.
  • Run-to-run spread. The file holds one median for each cell. One machine. One run. One 3 s window for each point (5 s for MiniLM). The file holds no repeats, so the size of run-to-run noise is not measured.
  • One batch size only (1).
