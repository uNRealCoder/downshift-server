The question

One downshift process runs inference on one machine. --workers N starts N processes. This page shows what that does to throughput at 1, 8 and 32 concurrent clients.

Method

  • The workers sweep is the last part of python -m bench.run --out bench/results/v0.5.0/results.json. It starts the real CLI with --workers 1, 2 and 4 on clean_mlp, mlp_large and bert_small. Batch 1, JSON.
  • With more than one worker, the parent exports once and hands the artifact to each worker.
  • Data: chart_runs.csv of the 0.5.0 run, rows with suite = workers.

What this shows and does not show

Shows

  • With 8 or more clients, throughput rises with the number of workers for all three models in both versions.
  • At c=1, more workers do not help. For bert_small 4 workers are slower than 1 (70 against 91 requests/s in 0.5.0).
  • Boot time grows with workers: it is longer with 4 workers than with 1 for every model.

Does not show

  • Linear scaling. The best case is 3.9x for 4 workers. The load generator shares the 16 logical CPUs with the workers, and its ceiling in this run was 8477 requests/s at c=8.
  • Results for 1.0.0rc1, for any other model, or for a machine with another core count.
  • The README of bench/ notes one startup hang in 0.4.0 (--workers 4 on bert_small did not answer /ready within 600 s once, then was re-run). The stored boot times are of the re-run.
  • One machine. One run. One 3 s window for each point (5 s for MiniLM). The file holds no repeats, so the size of run-to-run noise is not measured.
