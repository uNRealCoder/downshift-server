downshift benchmarks

downshift serves a PyTorch model over HTTP. Before the first request, it checks that the ONNX version of the model gives the same numbers as PyTorch. These pages show what that check finds and what it costs.

Run 2026-11-07T22:59:00. win32, 16 logical CPUs, Python 3.12.10, torch 2.14.0+cpu, onnxruntime 1.30.0. downshift 1.0.0rc1 from the checkout, 0.5.1 from PyPI. The folder is named v1.0.0, but its data is from the release candidate 1.0.0rc1. Hardware: not recorded in these runs (the files hold the CPU count only).

In 60 seconds

  1. The problem. torch.onnx.export can finish with no error and still give a graph with wrong numbers.
  2. The check. downshift exports the model in memory. It runs 8 samples through PyTorch and through ONNX Runtime. Some samples have shapes that the exporter did not see. It compares the outputs.
  3. The verdict. CLEAN, DEGRADED, FAILED or UNVERIFIED. The verdict selects the backend: ONNX Runtime when the graph is right, eager PyTorch when it is not.
  4. An example from the data. The model scatter_include_self_false exports with no error. The check says: exported via strict=False but numerics diverge on 6/8 samples (max abs err 1.59e+00). A hand-rolled ONNX Runtime server returns answers that are off by 1.2e+00. downshift serves torch and is off by 2.8e-08.
  5. The cost. The check takes time at boot (19.2 s against 11.8 s for MiniLM). Each request does more work than in a hand-rolled server. On tiny models a hand-rolled server is faster (3216 against 1428 requests/s peak on clean_mlp).

How to read these pages

  • Every number comes from a file in bench/. Each page lists its sources at the end.
  • To find the proof of one capability, read CAPABILITIES.md. It names the result file and gives one number for each capability.
  • Each page has the same parts: the question, the method, the results, what the data shows, and what it does not show.
  • Charts have text labels. A table with the same numbers follows each chart.
  • Read the limits. All load results are from one machine, in one run, with no repeats.

What is not measured

  • GPU. The machine is CPU only (bench/REPORT_v0.4.0.md states this).
  • Linux or macOS. The machine is Windows.
  • TorchServe, BentoML, Triton, TEI and Infinity. No run includes them (bench/REPORT_v0.4.0.md, section Not measured).
  • The --workers sweep and Prompt Guard for 1.0.0rc1. Both ran in earlier runs only.
  • Run-to-run spread. No file holds repeats.
  • Text generation. downshift does not do it.
