Correctness under load

Do the servers return the right numbers? Every response in the load run was compared with eager PyTorch.

The question

A fast server with a wrong answer is not a win. The harness checks the answer of every server for every model, so a wrong row shows up next to its speed.

Method

  • All processes build the same model from seed 1234 (bench/cases.py). The reference output is eager PyTorch.
  • max_abs_err is the worst element-wise absolute error against the reference. The table shows the worst value over all rows of a server (every batch and concurrency).
  • The verdict is made by downshift check logic at the start of each downshift server. Tolerance: atol 1e-4, rtol 1e-3 for float32. A sample passes when abs(got - expected) <= atol + rtol * abs(expected) (docs/cli.md).
  • For MiniLM, every answer is compared with downshift --backend torch, and the file stores the minimum cosine similarity.

What this shows and does not show

Shows

  • The gate prevented a wrong answer on the one DEGRADED model in the run, and the cost in speed is the torch speed for that model.
  • On the CLEAN models, the ORT answers differ from torch by less than 1e-5 under load.
  • No request failed.

Does not show

  • How often a real model is DEGRADED. The run has one DEGRADED model, and the authors chose it to show the hazard. The compatibility page lists more.
  • The error on inputs that the harness did not send. Each row of the table compares one request of that shape.
  • Weights are random and seeded, not trained. Real trained models are in the compatibility page.
  • One machine. One run. One 3 s window for each point (5 s for MiniLM). The file holds no repeats, so the size of run-to-run noise is not measured.
