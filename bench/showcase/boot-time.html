Boot time: what the gate costs before the first request

How many seconds from process start to a ready server?

The question

The gate runs before the first request. It exports the model and runs 8 samples. This work takes time. This page shows how much, as the harness measured it.

Method

  • ready_s is the time from the start of the server process to the first 200 answer. downshift answers on /ready. The hand-rolled servers answer on /health (bench/hf_models.py). The ends are not the same event.
  • Each value is one measurement for one start. The CSV repeats it on every row of a server. The file has no repeats.
  • wall_s of downshift check on MiniLM comes from results_hf.json.

What this shows and does not show

Shows

  • On MiniLM, downshift is ready in 19.2 s. The hand-rolled server is ready in 11.8 s. The difference is 7.4 s.
  • With --backend torch, downshift is ready in 12.3 s.
  • On the four fixtures, downshift takes 3.4 to 4.6 s more than the hand-rolled torch server.

Does not show

  • How the boot time divides between load, export, verify and warm-up. The stored check report has no timing split. The README example shows such a split for one model.
  • Whether the 6.9 s gap between the default and --backend torch is the export and the check alone. The data does not say.
  • The effect of the export cache (--export-cache-dir). It is not measured here.
  • The boot time on Linux, or on another CPU. One machine. One run. One 3 s window for each point (5 s for MiniLM). The file holds no repeats, so the size of run-to-run noise is not measured.
