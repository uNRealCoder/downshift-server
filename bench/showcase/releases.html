Release to release

Did the peak throughput change between releases? Each comparison is inside one run, so the machine state is the same for both versions.

Run A: 2026-10-04T22:32:59 (0.4.0 and 0.5.0). Run B: 2026-11-07T22:59:00 (0.5.1 and 1.0.0rc1). Both on win32, 16 logical CPUs.

Rule.Do not compare numbers between run A and run B. The hand-rolled servers are faster in run B too, so the machine state is not the same. The reports say this. Compare the versions inside one run only.

The question

Each release changes the serving code. This page shows the change in peak requests per second, batch 1, JSON bodies, cache off, for each pair of versions that ran in the same session.

Method

  • Run A: bench/results/v0.5.0/ (8 models). Run B: bench/results/v1.0.0/ (4 models). Same harness, same commands. See the throughput page for the method.
  • Peak is the best requests/s over concurrency 1 to 64, from chart_runs.csv.
  • The 0.4.0 run of September 2026 (bench/results_v0.4.0.json, behind the launch post) is a separate run with an older harness. This page does not use it. Its files stay unchanged.

What this shows and does not show

Shows

  • 0.5.0 against 0.4.0: peak throughput rose on all 8 models, from +4% to +20% in the same session.
  • 1.0.0rc1 against 0.5.1: no gain, and no clear loss except the slow first pass of mlp_large.

Does not show

  • The final 1.0.0 release. Run B is of 1.0.0rc1.
  • Any release after 1.0.0rc1.
  • 0.5.1 against 0.5.0 (never in the same session).
  • One machine. One run. One 3 s window for each point (5 s for MiniLM). The file holds no repeats, so the size of run-to-run noise is not measured.
